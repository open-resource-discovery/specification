## General Tool, Framework and Library Support

The [ORD presentation](https://open-resource-discovery.github.io/presentation/) provides a visual walkthrough of these projects and the tasks they support.
Its [source](https://github.com/open-resource-discovery/presentation) is available on GitHub.

### Build and Publish

- [Spec Toolkit](https://github.com/open-resource-discovery/spec-toolkit) generates JSON Schema specification documentation and related artifacts.
- [ORD Provider Server](https://github.com/open-resource-discovery/provider-server) serves static ORD metadata from local files or a GitHub repository.
- [Spring Boot Starter for ORD](https://github.com/open-resource-discovery/spring-boot-starter-ord) adds annotation-generated or static ORD endpoints to Spring Boot applications.
- [ORD Maven](https://github.com/open-resource-discovery/ord-maven) publishes generated Java models and annotations for ORD.

### Explore and Present

- The [ORD Reference Application](https://ord-reference-application.cfapps.sap.hana.ondemand.com/) is a running Provider with public [source code](https://github.com/open-resource-discovery/reference-application).
  Its embedded Explorer displays public or demo-authenticated tenant-specific metadata and native definitions.
- [ORD Explorer](https://open-resource-discovery.github.io/explorer/) connects to an ORD Provider and lets users browse its catalog, relationships, and native resource definitions.
- [Metadata Renderer](https://github.com/open-resource-discovery/metadata-renderer) renders supported native metadata formats through one React API.
- [ORD UI Components](https://github.com/open-resource-discovery/ui-components) provides the shared accessible and themeable React components used by the tool UIs.

### Create and Apply ORD Overlays

- [ORD Overlay Editor](https://open-resource-discovery.github.io/overlay-editor/) provides a browser playground and React components for viewing and editing overlays.
- [ORD Overlay Tools](https://github.com/open-resource-discovery/overlay-tools) provides a TypeScript library and CLI for validating, dry-running, converting, and applying overlays.
- [ORD Overlay for Go](https://github.com/open-resource-discovery/overlay-golang) applies overlays to supported native definition formats from Go.

### AI and Agent Workflows

ORD can describe and relate agent and protocol metadata.
The following adjacent tools help developers inspect and test those native formats and interactions.

- [A2A Editor](https://open-resource-discovery.github.io/a2a-editor/playground) and the [A2A Editor extension for VS Code](https://github.com/open-resource-discovery/a2a-editor-vscode) support Agent Card editing, validation, and protocol testing.
- [A2A Sample Server](https://github.com/open-resource-discovery/a2a-sample-server) provides test agents, while the [ORD and A2A demo](https://github.com/open-resource-discovery/a2a-ord-demo) demonstrates ORD discovery followed by A2A communication.
- [MCP Server Card UI](https://open-resource-discovery.github.io/mcp-server-card-ui/playground) supports Server Card editing, validation, and MCP server testing.
- The [ORD MCP Server Card demo](https://github.com/open-resource-discovery/ord-mcp-server-card-demo) compares manual MCP setup with ORD-based discovery and static Server Card metadata.
- [Metadata Compactor for Go](https://github.com/open-resource-discovery/metadata-compactor-golang) reduces metadata with configurable rules for more efficient use in LLM context.

### Framework Support

- [SAP ABAP Platform](https://developers.sap.com/topics/abap-platform.platform.html), including ABAP Cloud has inbuilt ORD support.
- [SAP CAP](https://cap.cloud.sap/docs/) framework has an [open source ORD plugin](https://github.com/cap-js/ORD).
